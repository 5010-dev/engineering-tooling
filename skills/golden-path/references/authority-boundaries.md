# Authority boundaries

Read the current source rather than relying on this summary when exact policy text matters.

- Organization policy owns the Developer Tooling Standard, retained schemas, guides, and decisions.
- Golden Path guidance owns supported journeys, defaults, copy-once examples, and checklists.
- Each repository owns native manifests and locks, toolchain selectors, native roots, Just graph, canonical CI, release and deployment workflows, dependency automation, security routing, and exceptions.
- Current CI, release, deployment, alert, and pull-request state is evidence, not permanent policy meaning.
- Historical `engineering-tooling` tags and releases are immutable audit history for the retired executable line.
- The developer-installed package and Skill are explicit local support. They do not approve, enforce, publish, deploy, mutate consumers remotely, or maintain organization state.

When these sources conflict, use the current reviewed standard first and preserve repository-native As-built facts unless the standard requires a reviewed change.
